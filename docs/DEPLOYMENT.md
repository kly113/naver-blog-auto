# 배포와 실제 검증 상태

이 저장소는 기존 PR #1의 프로젝트를 확장합니다. 소스와 배포 구성은 인터넷 배포 자체와 다릅니다. 서비스 생성·HTTPS URL 응답 확인 전에는 배포 완료로 보고하지 않습니다.

## 사용자에게 필요한 외부 승인

Render 계정과 이 GitHub 저장소를 읽을 수 있는 연결이 필요합니다. `render.yaml`로 웹 서비스와 비공개 자동화 서비스를 함께 생성합니다. 사용자는 웹 화면에서 계정 연결·권한·유료 서비스 요금을 승인하며, 코드를 수정하거나 터미널을 사용할 필요가 없습니다. 현재 Blueprint는 웹 Starter, 작업 서버 Standard, 10GB 영구 디스크를 요청합니다. 공식 가격표 확인 시 웹 $7/월, 작업 서버 $25/월, 10GB 디스크 $2.50/월로 기본 약 $34.50/월입니다(2026-10-13 확인). OpenAI 사용료·추가 트래픽 등은 별도이며, 최종 금액은 Render 승인 화면에서 확인해야 합니다.

`APP_OWNER_PASSWORD`는 이 사이트 전용 접속 비밀번호(12자 이상)로, 네이버 비밀번호가 아닙니다. `BLOG_AI_API_KEY`는 글 생성에 사용할 OpenAI API 연결이며 Render의 보안 입력란에만 입력합니다. 대화나 Git에 값을 남기지 않습니다. 네이버 로그인 비밀번호는 어떤 환경 변수나 설정에도 등록하지 않습니다.

웹 서비스의 HTTPS 주소가 생성되면 `/api/health`가 200인지 확인하고, 익명 접근은 `/login`으로 이동하는지 검증합니다. 사용자는 사이트 접속 → 네이버 연결 → 공식 화면에서 로그인 → 로그인 완료 확인 → 블로그·게시판 선택 → 콘텐츠 등록 순서로 이용합니다.

## 실행 환경 분리

- `deploy/Web.Dockerfile`: Next.js standalone 웹 서버. 브라우저·쿠키·사진·DB를 보관하지 않습니다.
- `Dockerfile`의 마지막 worker 단계: Node.js 24, Chromium, Python/Pillow. 공개 엔드포인트가 없는 Render private service로 배치합니다.
- 서비스 간 요청은 내부 네트워크와 별도 256비트 토큰으로 보호합니다. 웹 요청에도 관리자 세션 검사가 추가로 적용됩니다.
- 영구 디스크의 SQLite에 작업·사진·발행 이력·해시 처리 기록을 저장합니다. 로그인 쿠키는 AES-256-GCM으로 암호화하고, 키는 보안 환경 설정에 분리합니다.
- 디스크와 세션 암호화 키는 함께 유지해야 합니다. 키를 바꾸면 이전 세션은 복호화되지 않으므로 사용자 재로그인이 필요합니다. 비밀번호/원격 키 입력/화면을 로그·HAR·영상으로 저장하지 않습니다.
- 하나의 배포는 한 명의 소유자 전용입니다. 여러 고객을 함께 수용하는 서비스가 아니며, 고객별로 배포·디스크·키를 분리해야 합니다.

## 아직 완료되지 않은 실제 연동

SaveFrom 자동 사진 추출은 실제 접근과 사진 전체 수량의 검증이 필요합니다. 보안 확인을 우회하지 않습니다. 전체 장수를 확인할 수 없으면 사용자 확인 또는 직접 업로드로 전환하며, 성공을 가장하지 않습니다.

네이버 카테고리/발행 목록/편집기는 변경될 수 있는 웹 화면 어댑터입니다. 실제 로그인 계정으로 블로그 소유 확인, 전체 기록 조회, 사진 순서, 가운데 정렬, 카테고리 선택, 스티커 삽입, 임시저장, 발행 URL을 검증해야 합니다. 현재 **스티커 자동 삽입은 구현·실제 검증되지 않았고**, 공식 편집기에서 직접 선택하는 경로만 제공합니다. 본문 자동 입력과 최종 발행 조작도 실제 네이버에서 검증되지 않았습니다.

자동 발행은 기본 차단됩니다. 환경 플래그 하나만 켜도 활성화되지 않습니다. 실제 검증의 게시물 URL과 편집기·카테고리·스티커·발행 결과 증거를 내부 `live-naver-verification` 기록에 남기고 `NAVER_AUTOPUBLISH_VERIFIED=true`를 적용한 후에만 사용할 수 있습니다. 이 기록을 임의로 만들거나 테스트 대역 결과로 채우면 안 됩니다. 실제 검증을 수행하는 개발 작업에서만 증거를 등록합니다. 현재 릴리스에는 해당 증거가 없습니다.

발행 클릭 이전에 SQLite의 발행 시도 잠금을 기록합니다. 결과가 불명확하면 `verification_required`로 전환하고 재발행 버튼과 재시도를 차단합니다. 실제 네이버 게시물 URL을 읽어서 결과를 대조하는 절차가 필요합니다. 외부 네이버 서비스와 DB 사이에 원자적 트랜잭션은 없으므로 무조건적인 exactly-once 발행을 보장하지 않습니다.

## 배포 후 확인할 항목

1. HTTPS 관리자 로그인, 익명 API/사진/공식 브라우저 접근 차단, 로그아웃 후 세션 폐기.
2. 본인 소유/사용 허락이 있는 사진 여러 장 업로드 → Python 실제 2배 크기 → 원본과 색상 비교 → 다운로드 ZIP 안의 전체 사진 확인.
3. OpenAI 실제 키로 사진+본문 분석과 사실 기반 초안 생성(테스트 대역을 사용한 결과와 구분).
4. 네이버 공식 로그인과 보안 절차 직접 완료, 본인 블로그/카테고리 자동 조회.
5. 네이버 기존 기록 비교가 모든 글과 사진을 포함하는지 확인. 불완전/오류는 완료 처리하지 않음.
6. 사용자 승인된 실제 글로 편집기·스티커·임시저장·발행·게시물 URL 검증. 실패 후 재시도/재시작에서 중복 발행하지 않는지 확인.
7. 작업 서버를 재시작해 사진·작업·암호화 세션이 유지되고, 진행 중 발행은 자동 반복되지 않는지 확인.

이 검증과 계정 연결이 끝나기 전에는 요청한 전체 자동 발행 흐름이 완성됐다고 보고하지 않습니다.
