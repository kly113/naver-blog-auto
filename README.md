# 블로그 스튜디오 · Naver Blog Auto

사진으로 네이버 블로그 글을 준비하는 **한 명의 소유자 전용 웹 프로그램**입니다. 기존 PR #1의 프로젝트를 이어서 개발합니다.

현재 여러 사진 업로드 → 실제 Python 2배 확대 → 원본/확대 이미지 중복 검사 → 글 수정·가운데 정렬 미리보기 → 본문·사진 다운로드와 작업 기록을 연결했습니다. OpenAI 사진 분석·글 생성과 공식 네이버 브라우저 연결 어댑터도 포함합니다. **실제 계정 로그인·네이버 편집·스티커 자동 삽입·자동 발행은 아직 검증 완료되지 않았고, 자동 발행은 차단되어 있습니다.** 전체 자동 발행 서비스가 완성됐다고 주장하지 않습니다.

## 인터넷 사이트로 배포하기

[Render 배포 승인 화면 열기](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fkly113%2Fnaver-blog-auto%2Ftree%2Ffeat%2Fadmin-automation-foundation)

위 화면에서 Render 계정 로그인, 이 GitHub 저장소에 대한 접근 연결, 생성할 유료 서비스·영구 디스크의 요금을 확인하고 승인합니다. 코드 수정이나 터미널 작업은 필요하지 않습니다. 배포 계정 연결과 승인이 완료되기 전에는 실제 인터넷 서비스 주소가 존재하지 않습니다. 자세한 구성과 검증 제한은 [배포 안내](docs/DEPLOYMENT.md)에 있습니다.

배포 화면에서 입력할 값은 다음과 같습니다. 대화나 Git에 값을 남기지 마세요.

- `APP_OWNER_PASSWORD`: 이 사이트를 열 때 사용할 전용 접속 비밀번호(12자 이상). 네이버 비밀번호가 아닙니다.
- `BLOG_AI_API_KEY`: OpenAI 글 생성에 사용할 API 키. 제공하지 않으면 사진 확대와 직접 작성은 가능하지만 AI 자동 작성은 실행하지 않습니다.

작업 서버와 웹 서버를 따로 배포하며, 작업 서버는 공개 주소 없이 내부 네트워크에 배치합니다. 서비스 간 토큰과 세션 암호화 키는 Render가 자동 생성합니다. 네이버 비밀번호를 설정하는 항목은 없습니다. 배포 후 실제 HTTPS 사이트의 응답을 확인해야 배포 성공으로 판단합니다.

## 웹사이트 사용 순서

1. 사이트 접속 비밀번호로 내 스튜디오를 엽니다.
2. **네이버 연결**에서 공식 로그인 화면을 열고 그 화면 안에서 아이디·비밀번호·필요한 보안 확인을 직접 완료합니다. 입력 내용과 비밀번호는 프로그램에 저장하지 않습니다.
3. **로그인 완료 확인**으로 본인 블로그와 게시판을 조회하고 선택합니다. 화면 구조 변경이나 조회 실패가 있으면 연결 성공으로 처리하지 않습니다.
4. 인스타그램 게시물·릴스 URL, 원본 본문, 확인된 지역·시술 정보를 입력합니다. 사용 권한을 확인하고 **자동화 시작**을 누릅니다.
5. SaveFrom 사진 추출을 먼저 시도합니다. 접속 실패·보안 확인·전체 사진 수량 불확실은 화면에 표시합니다. 원본 사진을 직접 여러 장 업로드하거나 추출된 사진이 빠짐없이 포함됐는지 확인해 이어갑니다.
6. 확대 사진과 글을 미리보기에서 확인합니다. AI 연결이 없으면 직접 제목·본문·태그를 작성할 수 있습니다. 직접 작성한 글을 AI 결과로 표시하지 않습니다.
7. 현재 자동 발행이 제한되어 있으므로 **본문과 확대 사진 다운로드** 또는 **네이버 공식 편집기에서 완료**를 이용합니다. 스티커·임시저장·카테고리·발행은 공식 네이버 화면에서 직접 확인합니다. 편집기 자동 입력도 현재 실제 네이버에서 검증되지 않았으며 실패 시 다운로드 경로로 안내합니다.
8. 수동 발행을 완료한 뒤 실제 네이버 게시물 URL을 입력하면, 연결된 본인 블로그의 제목·본문·사진을 읽어 결과를 확인합니다. 결과가 불명확하면 새 글을 다시 발행하지 말고 기존 글을 먼저 확인하세요.

## 기능과 검증 경계

| 기능 | 현재 구현 |
| --- | --- |
| 관리자 접속 보호 | HttpOnly/SameSite=Strict 세션, 운영 환경 Secure 쿠키, 로그아웃 시 서버에서 세션 폐기 |
| 원본 사진 업로드 | 정적 JPG·PNG·WebP, 각 10MB 이하, 최대 20장, 한 요청 총 80MB 이하 |
| 2배 확대 | Python Pillow Lanczos, 생성형 보정 없음, EXIF 방향 적용 및 위치 메타데이터 제거 |
| 중복 검사 | URL 정규화, SHA-256 파일/픽셀, 원본·확대 사진 dHash 유사도 |
| AI 초안 | 사진 전체·본문·확인된 정보 입력, 구조화된 제목/문단/사진 순서/해시태그 검증. 실제 API 연결 검증은 키 필요 |
| 글 수정·미리보기 | 가운데 정렬, 문단 여백, 사진 순서, 모바일 너비 |
| 다운로드 | 실제 확대 사진 전체 + HTML 미리보기 + 본문 + 수동 완료 안내 ZIP |
| 작업 기록 | SQLite 영구 저장, 재시작 후 작업·사진 유지, 중단된 발행의 자동 반복 차단 |
| 네이버 연결·카테고리·기존 글 조회 | 공식 브라우저 어댑터 구현, 실제 로그인 계정 검증 필요 |
| 네이버 편집·스티커·발행 | 글 입력/발행 어댑터는 미검증, 스티커 자동 삽입은 미구현. 공식 화면의 수동 경로 제공, 자동 발행 기본 차단 |

확대는 사진을 생성하는 AI 초해상도가 아닌 보간 처리입니다. 새로운 얼굴·머릿결을 합성하지 않습니다. 기존의 머리 색상·피부톤을 새롭게 보정하지 않으며, 실제 사진의 시각적 품질은 사용자 사진으로 비교해야 합니다. 2배 확대 출력은 최대 1억 화소입니다.

유사도 검사는 리사이즈를 고려하지만 모든 크롭·회전·색상 필터를 판별하지 못하고 오탐도 가능합니다. 중복 감지는 자동 진행을 멈추며 기존 작업이나 기존 게시물 URL을 표시합니다. 기존 네이버 기록을 모두 읽지 못하면 '비교 완료'로 표시하지 않고 자동 발행을 제한합니다.

자동 발행은 명시적 사용자 활성화와 실제 네이버 검증 증거가 필요합니다. 환경 플래그 하나만 바꿔도 켜지지 않습니다. 발행 시도는 클릭 전에 DB에 기록하고, 응답이 불명확하면 재시도를 차단합니다. 외부 네이버와 로컬 DB 사이의 무조건적인 원자적 exactly-once 처리를 보장하지 않습니다.

## 개발 설치

개발자는 Node.js 24, Python 3.12를 사용합니다. 배포 Docker 작업 서버는 Debian의 Python 3.11과 고정한 Pillow 12.0을 사용하며 컨테이너에서도 실제 처리 검증을 수행합니다.

```bash
npm ci
python3 -m venv .venv
.venv/bin/python -m pip install -r python/requirements.txt
npm run db:init
```

`.env.example`의 설정 이름을 참고해 로컬 `.env.local`을 만듭니다. 사이트 접속 비밀번호는 안전한 별도 값으로 지정합니다. 네이버 비밀번호를 적지 마세요. 인증 값은 커밋하지 않습니다.

```bash
npm run dev:all
```

이 명령은 로컬 웹과 작업 서버를 함께 실행합니다. 작업 서버의 로컬 통신·암호화 키는 처음에 `data/local-worker-keys.json`에 권한 600으로 생성하고 재사용합니다. 이 파일과 `data` 전체를 비공개로 유지하세요. `npm run dev`만 실행하면 작업 서버도 별도로 필요합니다. 사용자용 실제 서비스는 Render가 부여한 HTTPS 주소를 사용합니다.

| 서버 설정 | 용도 |
| --- | --- |
| `WORKER_URL` | 웹이 연결할 내부 작업 서버 주소 또는 host:port |
| `WORKER_AUTH_TOKEN` | 서비스 간 별도 인증 값(24자 이상, 생성 시 256비트) |
| `APP_OWNER_PASSWORD` | 사이트 소유자 접속 비밀번호(12자 이상) |
| `SESSION_ENCRYPTION_KEY` | 네이버 세션 AES-256-GCM 키의 고엔트로피 시드(32자 이상) |
| `DATA_DIR` | SQLite·개인 사진·암호화 세션 보관 경로 |
| `BLOG_AI_API_KEY` | OpenAI API 키. 서버에서만 사용하며 기존 `OPENAI_API_KEY`도 지원 |
| `BLOG_AI_MODEL` | 기본 `gpt-4.1-mini` |
| `APP_PUBLIC_URL` | 실제 공개 HTTPS 주소. Render에서는 자동 제공하는 `RENDER_EXTERNAL_URL` 사용 가능 |
| `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` | 시스템 Chromium 경로 |
| `PYTHON_EXECUTABLE` | 작업 서버 Python 실행 파일 경로 |
| `NAVER_AUTOPUBLISH_VERIFIED` | 기본 false. 실제 내부 검증 증거가 없는 상태에서는 true여도 자동 발행 차단 |

원본 DB 테이블은 유지하고 작업·사진·세션·발행 기록용 테이블을 추가합니다. 데이터는 웹 서버에 두지 않고 비공개 작업 서버의 영구 디스크에 보관합니다. 사진이나 암호화 키를 공개 저장소·정적 파일 경로에 넣지 마세요.

## 검증 명령

```bash
npm run test
npm run build
npm run typecheck
.venv/bin/python -m unittest discover -s python -v
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

E2E는 별도 데이터 디렉터리, 포트 3100 웹/4100 작업 서버를 사용하며 테스트용 소유자 비밀번호만 설정합니다. 실제 네이버/인스타그램/OpenAI를 호출하지 않는 흐름과 실제 외부 서비스 검증을 구분합니다. 테스트 실행 시 `data`의 사용자 파일을 삭제하지 않습니다.

배포 이미지 자체 검증:

```bash
docker build --target worker -t naver-blog-worker:local .
docker build -f deploy/Web.Dockerfile -t naver-blog-web:local .
.venv/bin/python tests/container_smoke.py
```

검증 스크립트는 테스트 전용 컨테이너·볼륨·고엔트로피 임시 값을 생성하고, 실제 운영 이미지의 인증·Python 확대·색상 보존·ZIP·재시작 영속성·로그아웃을 확인한 뒤 자신이 생성한 자원만 정리합니다. 클라우드 프록시가 있는 빌드 환경은 지원되는 프록시 경로와 공개 CA 묶음을 BuildKit `build_ca` 임시 마운트로 공급해야 할 수 있습니다. TLS·패키지 서명·잠금 파일의 무결성 검사는 끄지 않습니다. 이 공개 CA는 이미지에 복사하지 않습니다.

## 구조

```text
src/app/                 Next.js 페이지, 인증, 작업 서버 게이트웨이
src/components/          콘텐츠 준비·작업 상태·미리보기·공식 원격 브라우저 화면
src/lib/workflow/        작업 저장, 사진 처리, AI, 중복, 세션, 네이버 어댑터
src/lib/automation/      Chromium 생성 및 지원되는 프록시 설정
worker/                  영구 실행하는 비공개 작업 서버
python/                  2배 이미지 확대 CLI
render.yaml              웹 + 비공개 작업 서버 + 영구 디스크 배포 구성
Dockerfile               비공개 작업 서버 이미지
deploy/Web.Dockerfile    브라우저 없는 웹 이미지
tests/                   저장·보안·실제 처리·웹 E2E·컨테이너 검증
```

클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 사용하고 별도 Git worktree를 만들 필요가 없습니다. 환경 설정의 설치·시작 지침 저장은 인터넷 배포가 아닙니다. 공개 계정 승인과 실제 서비스 URL 검증은 별도로 완료해야 합니다.
